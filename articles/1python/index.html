Set集合

set 里面只会存在非重复的元素，不管你往里面加了多少相同元素，这些相同元素都会坍缩成一个。这种特性，我们就可以运用它来做交集并集等操作。注意，在集合中的元素，其实是没有顺序的。

print(my_files)# {'file4', 'file2', 'file3', 'file1'}
my_files.remove("file3")
print(my_files)# {'file4', 'file2', 'file1'}

深浅拷贝

AI 实战场景：处理数据集、配置字典时，= 赋值只是贴标签，修改副本会把原始数据也改掉。深浅拷贝是解决这类隐蔽bug的关键。 直接赋值=：只是给同一个对象起了新名字，内存中仍是同一个东西。 用 C 语言（指针）的思维来理解 Python 的话：

  • a = [1, 2, [3, 4]] 时，Python 先在内存中创建了这个列表对象，然后让 a 指向（引用）它。
  • b = a 时，Python 并没有新建对象，只是让 b 也指向同一个内存地址。
  • 所以 a 和 b 是两个名字（指针/引用），但指向同一块内存。
a = [1, 2, [3, 4]]
b = a
b[0] = 99
print(a)  # [99, 2, [3, 4]] —— a 也被改了！

可以试着用id()验证，输出的地址一致：

print(id(a))  # 比如 140234567890
print(id(b))  # 也是 140234567890，同一个地址

如图：

变量名                    内存中的对象
    ┌─────────┐              ┌─────────────────────┐
    │    a    │─────────────→│                     │
    └─────────┘   引用        │   [99, 2, [3, 4]]  │
                             │    ↑ 修改后的值     │
    ┌─────────┐              │                     │
    │    b    │─────────────→│   同一个列表对象     │
    └─────────┘   引用       │   id: 0x7f8b2c...   │
                            └─────────────────────┘
           a is b  →  True  （同一个身份/地址）
           a == b  →  True  （值也相等）

浅拷贝copy()：创建一个新容器，但里面的嵌套对象仍是引用，也就是你修改嵌套对象会同时修改原对象。简单说，就是一维的元素拷贝了数值过来，高维的元素/列表等等，拷贝的是引用。

import copy
a = [1, 2, [3, 4]]
b = a.copy()      # 或 list(a)、切片 a[:]
b[0] = 99
print(a)          # [1, 2, [3, 4]] —— 外层没被改
b[2][0] = 999
print(a)          # [1, 2, [999, 4]] —— 内层列表还是被改了！

再举一个字典的例子：

import copy

config = {
    "model": "gpt-4",
    "params": {"temperature": 0.7, "max_tokens": 2000}
}

config_b = config.copy()          # 浅拷贝
config_b["model"] = "gpt-3.5"     # ✅ 不影响原 config
config_b["params"]["temperature"] = 1.0  # ❌ 原 config 的 temperature 也变成 1.0 了！

print(config["params"]["temperature"])  # 1.0 —— 中招了

深拷贝deepcopy()：递归复制所有嵌套对象，完全独立，对里面的任何嵌套对象的修改都不影响原来的a指向的对象。

import copy
a = [1, 2, [3, 4]]
b = copy.deepcopy(a)
b[2][0] = 999
print(a)          # [1, 2, [3, 4]] —— 完全独立，互不影响
方式写法外层独立？内层独立？适用场景
直接赋值b = a❌❌不需要复制，只是起别名
浅拷贝a.copy()✅❌一维列表、简单字典的复制
深拷贝copy.deepcopy(a)✅✅嵌套数据结构、AI配置字典、模型参数副本

列表推导式（一行搞定新列表）

用表达式替代 for 循环来创建列表，简洁到一行代码。 列表推导式是 Python 中最受欢迎的特性之一。

基本语法 [表达式 for 变量 in 可迭代对象 if 条件]。Python 底层用 C 快速迭代，比手动 for 循环 append 效率更高。 例：

# 基础：平方数
squares = [x**2 for x in range(10)]
print(squares)  # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

# 带条件：只保留偶数
evens = [x for x in range(10) if x % 2 == 0]
print(evens)   # [0, 2, 4, 6, 8]

# 嵌套循环：扁平化二维列表
# [表达式 for 外层变量 in 外层可迭代对象 for 内层变量 in 内层可迭代对象]，从左到右就是从外到里
matrix = [[1, 2], [3, 4], [5, 6]]
flat = [x for row in matrix for x in row]
print(flat)    # [1, 2, 3, 4, 5, 6]

字典/集合推导式：同样的语法也适用于 dict 和 set。

# 字典推导式
square_dict = {x: x**2 for x in range(5)}
print(square_dict)  # {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}

# 集合推导式：去重
nums = [1, 2, 2, 3, 3, 3]
unique_squares = {x**2 for x in nums}
print(unique_squares)  # {1, 4, 9}

zip（拉链式合并）

把多个列表按位置”拉”在一起，一一配对。 就像拉链一样，把两条链的对应齿牙咬合。

专业解释：zip() 接收多个可迭代对象，返回由元组组成的迭代器(zip 返回的是迭代器，用 list() 转成列表才能看到内容)，每个元组包含各对象同一位置的元素。结果长度以最短的输入为准。 通俗理解：你有两份名单 —— 名字列表和分数列表，zip 把对应位置的名字和分数”绑”成一对。

names = ["Tom", "Jerry", "Spike"]
scores = [85, 92, 78]

# 合并成 (名字, 分数) 对
pairs = list(zip(names, scores))
print(pairs)  # [('Tom', 85), ('Jerry', 92), ('Spike', 78)]

# 在循环中直接拆包
for name, score in zip(names, scores):
    print(f"{name}: {score}分")

多列表合并：

ids = [1, 2, 3]
names = ["Alice", "Bob", "Carol"]
roles = ["admin", "user", "user"]

users = list(zip(ids, names, roles))
print(users)  # [(1, 'Alice', 'admin'), (2, 'Bob', 'user'), (3, 'Carol', 'user')]

反解压：用 * 把 zip 结果拆回多个列表。

zipped = [('Tom', 85), ('Jerry', 92), ('Spike', 78)]
names, scores = zip(*zipped)
print(names)   # ('Tom', 'Jerry', 'Spike')
print(scores)  # (85, 92, 78)

长度不一致时：zip 以最短的为准，长的列表多余部分被忽略。

Function函数

定义函数

比如一个修改文件名的函数：

def modify_name(filename):
    filename += ".txt"
    filename = "my_" + filename
    print(filename)

f1 = "f1"
modify_name(f1)# my_f1.txt

其实一个函数也可以没有输入参数。 如果我们还想拿出来函数处理的结果，其实也就是让函数可以 return 出来一个值：

def modify_name(filename):
    filename += ".txt"
    filename = "my_" + filename
    return filename

new_filename = modify_name("f1")
print(new_filename)

参数设置

传入参数太多，可以写出参数名避免搞混：

def f(x, a, b, c):
    return a*x**2 + b*x + c*1

print(f(2, 1, 1, 0))    # 忽略参数名，按顺序传参

类型注解（Type Hints）

给函数的参数和返回值”贴上标签”，写清楚要什么类型、返回什么。 现代 Python 后端的标配，FastAPI、Pydantic 都基于它。

解释：Python 3.5+ 引入的可选类型注解，通过 : type 标注参数类型，-> type 标注返回值类型。运行时不会强制检查，但 IDE 和 mypy 等工具可以静态分析，提前发现类型错误。 通俗理解：就像快递包裹上的标签 —— 写了里面是什么（参数类型）、送到哪去（返回值类型），快递员（IDE）一看就知道怎么处理。 联系一下C语言： C语言中的一个函数，比如链表反转函数：void reverse(ListNode *s, int start, int end)，直接告诉编译器返回void类型，以及输入ListNode指针类型的s和两个int变量，这是必须声明的；而python里面的类型注解写不写都行，写了编译器也不看，更多的是一个提示的作用。

def add(x: int, y: int) -> int:
    return x + y

迭代器与生成器

处理大量数据而不爆内存的核心技术。 生成器（yield）按需逐个产出值，而不是一次性返回所有数据。FastAPI 流式响应、大文件处理、批量推理都依赖它。

# 生成器版大文件读取（省内存）
def chunk_reader(file_path, chunk_size=1024):
    with open(file_path, 'r') as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            yield chunk

# 批量处理数据（Agent/AI 常见模式）
def batch_items(items, batch_size=32):
    for i in range(0, len(items), batch_size):
        yield items[i:i + batch_size]

for batch in batch_items(range(100), 32):
    print(batch)  # [0..31], [32..63], [64..95], [96..99]

和 return 的区别：

方式一次性？内存占用适用场景
return 列表是高小数据
yield 生成器按需逐个产出低（只存当前值）大文件、流式数据、无限序列

生成器本质是实现了迭代器协议的函数，你也可以手动实现迭代器：

class Counter:
    def __init__(self, n):
        self.n = n
        self.current = 0
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if self.current < self.n:
            self.current += 1
            return self.current
        raise StopIteration

装饰器

不修改原函数代码，给函数”套壳”增加功能。 FastAPI 的 @app.get("/")、@app.post("/") 就是装饰器。理解装饰器才能理解框架在做什么。

先看一个最简例子，理解”函数能当参数传，也能在函数内部定义并返回”：

def add_star(func):        # ① 接收一个函数
    def wrapper():         # ② 内部定义一个新函数
        return "⭐ " + func() + " ⭐"
    return wrapper         # ③ 返回这个新函数

@add_star                  # 等价于 say_hi = add_star(say_hi)
def say_hi():
    return "你好"

print(say_hi())  # ⭐ 你好 ⭐

@add_star 执行时：把 say_hi 传入 add_star → wrapper 包裹了原函数 → 返回的 wrapper 重新赋值给 say_hi。所以现在调用 say_hi() 实际在调用 wrapper()。

再看一个”调用前后加边框”的例子，结构完全一样：

def add_border(func):
    def wrapper():
        print("=" * 10)          # 调用前
        func()                   # 调用原函数
        print("=" * 10)          # 调用后
    return wrapper

@add_border
def say_hi():
    print("你好")

say_hi()
# ==========
# 你好
# ==========

带参数的装饰器：三层层层嵌套。为什么需要三层？因为 @log("INFO") 等价于 delete_file = log("INFO")(delete_file)——先调 log("INFO") 返回一个装饰器，再拿这个装饰器去装饰函数。

def log(level):                 # ① 第一层：接收装饰器自己的参数
    def decorator(func):        # ② 第二层：接收被装饰的函数（这才是真正的装饰器）
        def wrapper(msg):       # ③ 第三层：包裹原函数，接收原函数的参数
            print(f"[{level}] {msg}")   # 用到了第一层的 level
            func(msg)           # 调用原函数
        return wrapper
    return decorator

@log("INFO")                    # 等价于：delete_file = log("INFO")(delete_file)
def delete_file(filename):
    print(f"删除 {filename}")

delete_file("old.txt")
# [INFO] old.txt
# 删除 old.txt

保留原函数信息：用 functools.wraps 让被装饰函数保留 __name__ 等元信息。

from functools import wraps

def add_border(func):
    @wraps(func)   # 保留 func 的 __name__、__doc__ 等，否则 print(say_hi.__name__) 会输出 wrapper
    def wrapper():
        print("=" * 10)
        func()
        print("=" * 10)
    return wrapper

Agent 开发场景：写工具函数（Tool）时，用装饰器自动注册、自动记录日志、自动处理异常，是 Agent 框架的基石。

Class类

Class定义

人类是一个对人的大统称，人类就是一个类。同样，如果推演到我们这个文件管理系统的背景，文件就是一个大类， 每个具体文件就是这个类下面的个体（每个人是人类下的个体）。 根据这样的逻辑，如果要生出来一个人，就得先有人类这个大概念，如果想创建一个文件，就要有文件这个大概念。 用 class File 来创建一个大概念（类），注意我们通常约定类的名字要首字母大写。 然后用 my_file = File() 来创建一个具体的文件。 每个具体的个体都带有这个类的基本属性，如 create_time, name。就像每个人都会有人类这个类当中的性别，年龄一样。

class File:
    def __init__(self):
        self.name = "f1"
        self.create_time = "today"

my_file = File()
print(my_file.name)
print(my_file.create_time)

 self 是作为类自己的一个索引，不管你在定义类的时候，想要获取这个类的什么属性或功能，都可以通过 self 来获取。 比如这个 File 类中，获取类自己的 create_time，就写成了 self.create_time。之后在说类的功能的时候， 也是通过 self 来在类内部调用的。  python的class有点类似c语言的结构体，但是：类=结构体+方法（函数），self类似参数，指向实例的引用，所有实例变量都要通过 self.xxx 来存取。 __ init __ 是一个初始化的方法，创建实例的时候会调用。 有了这些属性，我们除了就能获取属性，也能修改属性的值。

my_file.name = "new_name"
print(my_file.name)

Class功能

__init__ 是类的一个功能，那么就可以像函数那样当成真正的功能来使用。比如在 __init__() 里加上传入参数。并且在初始化 File() 的时候传入你要 __init__ 的参数。

class File:
    def __init__(self, name, create_time="today"):
        self.name = name
        self.create_time = create_time

my_file = File("my_file")
print(my_file.name)# my_file
print(my_file.create_time)# today

当然，除了__init__ 这种特殊的、创建对象自动执行的方法，自己也可以定义普通方法（函数），比如：

class File:

继承

继承 = “子类自动拥有父类的东西，同时可以添加或修改自己的特色”。父类：定义”通用装备”，比如汽车的共性是轮子、引擎；子类：继承+扩展，除了轮子、引擎，还有个性化的敞篷设计、前备箱等等。有了继承，一些有共性的地方在父类被设定好，就不用重复造轮子了，专注于差异化。

例如，视频文件和文本文件都有共性，他们都是文件File，都有名字name，和创建时间create_time，这些就可以在一个父类，即文件类；剩余的就是特殊属性，比如文本文件有语言language，视频文件有window_size。

class File:
    def __init__(self, name, create_time="today"):
        self.name = name
        self.create_time = create_time
    
    def get_info(self):
        return self.name + " is created at " + self.create_time

class Video(File):  # 继承了 File 的属性和功能
    def __init__(self, name, window_size=(1080, 720)):
        # 将共用属性的设置导入 File 父类
        super().__init__(name=name, create_time="today") # 父类的替身是super，这是用来调用父类的方法，能初始化共性的属性
        self.window_size = window_size

class Text(File): # 继承了 File 的属性和功能
    def __init__(self, name, language="zh-cn"):
        # 将共用属性的设置导入 File 父类
        super().__init__(name=name, create_time="today") 
        self.language = language
    
    # 也可以在子类里复用父类功能
    def get_more_info(self):
        return self.get_info() + ", using language of " + self.language

v = Video("my_video")
t = Text("my_text")
print(v.get_info())     # 调用父类的功能,my_video is created at today
print(t.create_time)    # 调用父类的属性,today
print(t.language)       # 调用自己的属性,zh-cn
print(t.get_more_info()) # 调用自己加工父类的功能,my_text is created at today, using language of zh-cn

魔法方法（Magic Methods）

双下划线开头结尾的特殊方法，让自定义类的对象像 Python 内置类型一样工作。__init__ 你已经会了，下面是最常用的几个。

# __call__：让实例能像函数一样被调用
class FileProcessor:
    def __init__(self, suffix):
        self.suffix = suffix
    
    def __call__(self, filename):
        return filename + self.suffix

add_txt = FileProcessor(".txt")
print(add_txt("my_file"))  # my_file.txt——实例被当作函数用了

# __len__ + __getitem__：让对象支持 len() 和 [] 索引
class FileList:
    def __init__(self, files):
        self.files = files
    
    def __len__(self):
        return len(self.files)
    
    def __getitem__(self, idx):
        return self.files[idx]

fl = FileList(["f1.txt", "f2.txt", "f3.txt"])
print(len(fl))       # 3
print(fl[1])         # f2.txt
for f in fl:         # 实现了 __getitem__，就支持 for 循环
    print(f)

# __str__ / __repr__：控制打印输出
class File:
    def __init__(self, name, size):
        self.name = name
        self.size = size
    
    def __str__(self):
        return f"File({self.name}, {self.size}KB)"     # 给人看的
    
    def __repr__(self):
        return f"File(name='{self.name}', size={self.size})"  # 给开发者看的

f = File("report", 256)
print(f)       # File(report, 256KB)
print(repr(f)) # File(name='report', size=256)
魔法方法触发方式用途
__init__obj = Class()初始化
__call__obj()实例当函数调用
__len__len(obj)返回长度
__getitem__obj[key]索引访问
__setitem__obj[key] = val索引赋值
__str__ / __repr__print(obj) / repr(obj)控制打印输出

文件管理与异常处理

读写文件

创建文件

f = open("new_file.txt", "w")   # 创建并打开,"w"表示写入。f = open("文件名+后缀","模式")
f.write("some text...")         # 在文件里写东西
f.close()                       # 关闭

新文件会在你运行的这个脚本的同级目录。

模式含义注意
“w”写入（write）文件已存在会清空覆盖
“r”读取（read）默认模式，文件不存在报错
“a”追加（append）在末尾添加，不覆盖
wb以二进制(binary)写入
rb以二进制读取
ab以二进制追加
如果你觉得要写一个 f.close() 或者有时候你怕自己忘记要 close()，或者程序执行到f.write("some text...")崩溃了（比如你写入了太多文字电脑内存不够了）导致close()没执行文件还损坏了, Python 人性化地提供了另外一种打开文件的方式。
这个方式把打开和关闭嵌入到了一个 with 架构中，即可以自动关闭。所以再也不用担心忘记关闭文件了。 下面这个案例，除了使用了 with 模式，我还换了一种写入数据的方式 writelines(), 当你传入像列表样的数据时， 列表中的每个元素就是一行记录，数据会分行来写。
注意，在列表里，每个元素最后都最好写一个\n来表示要另起一行。不然读出来的时候就黏在一起了。
with open("new_file2.txt", "w") as f:
    f.writelines(["some text for file2...\n", "2nd line\n"])

这里的writelines是写入字符串列表，而write是写入单个字符串。

读文件

上面说了，write写入，read读出：

f = open("new_file2.txt", "r")
print(f.read())
f.close()

read出来的结果是：

some text for file2...
2nd line

当然，如果你是writelines(list)写入的话，那么也可以用f.readlines(),最后print出来一个['some text for file2...\n', '2nd line\n']，对，就是纯正的包含换行符的列表，而不是文字。

大文件读取：逐行处理

AI 实战场景：处理日志、语料、批量推理结果时，文件往往几十MB甚至几个GB，f.read() 会一次性把整个文件塞进内存，容易爆掉。 此时应该用逐行读取。

readline()：每次只读一行，内存友好。

with open("big_log.txt", "r") as f:
    line = f.readline()      # 读第一行
    while line:
        print(line.strip())  # strip() 去掉末尾的 \n
        line = f.readline()  # 继续读下一行

更 Pythonic 的写法：直接用 for 循环迭代文件对象，底层就是逐行读取，简洁且安全。

with open("big_log.txt", "r") as f:
    for line in f:           # 每次只加载一行到内存
        print(line.strip())

**与 readlines() 的区别：

方法内存占用适用场景
f.read()高（整个文件）小文件，需要全文处理
f.readlines()高（整个文件变成列表）中小文件，需要按行索引
for line in f低（逐行）大文件、日志、流式语料处理
读取 JSONL（.jsonl）结果、处理爬虫日志时，务必用逐行读取，否则服务器内存会被拖垮。

异常处理try-except

程序出错不可怕，可怕的是程序直接崩溃。 异常处理让代码遇到问题时优雅降级，而不是当场挂掉。

基本结构

try:
    f = open("不存在的文件.txt", "r")
    content = f.read()
except FileNotFoundError:
    print("文件找不到，请检查路径")
except Exception as e:
    print(f"其他错误: {e}")
finally:
    print("无论成功失败，这段都会执行，适合收尾清理")

常见异常类型

异常类型触发场景Agent 开发示例
FileNotFoundError文件不存在读取知识库文件时路径写错
ValueError值类型/格式不对int("abc")、JSON 解析失败
KeyError字典中找不到这个 Key访问 result["choices"] 但 API 返回了错误格式
IndexError列表索引越界处理空列表时取 data[0]
TypeError类型不匹配字符串和数字直接相加

主动抛出异常

有时你不希望程序继续执行，可以主动 raise：

def load_config(path):
    if not path.endswith(".json"):
        raise ValueError("配置文件必须是 .json 格式")
    # ...

with 语句的底层原理

前面写的 with open(...) as f:，本质上是 try/finally 的语法糖：

# 这两段等价
with open("file.txt") as f:
    data = f.read()

f = open("file.txt")
try:
    data = f.read()
finally:
    f.close()      # 无论是否出错，都保证关闭文件

Agent 开发场景：调用 LLM API 时网络超时、返回非预期格式、本地文件缺失，都可以用 try/except 捕获并做降级处理（如重试、返回默认回复、记录错误日志），避免整个 Agent 流程中断。

JSON处理

后端 API 就是收发 JSON。 JSON 的格式长这样：{"name": "report.txt", "size": 1024}——就是 Python 字典的写法。所以 JSON 和 Python 字典之间来回转换是后端开发最频繁的操作。

Python 给你准备好了 json 这个标准库，不用自己安装，直接 import json 就能用。

序列化（dumps = dict → string）

import json

# 想象这个 data 是你后端从数据库查出来的数据，准备返回给前端
data = {"name": "report.txt", "tags": ["important", "draft"], "size": 1024}

# json.dumps = 把 Python 字典转成 JSON 格式的字符串，才能通过网络发送出去
json_str = json.dumps(data, indent=2, ensure_ascii=False)
print(json_str)
# 输出：
# {
#   "name": "report.txt",
#   "tags": ["important", "draft"],
#   "size": 1024
# }

反序列化（loads = string → dict）

# 反过来：前端给你发了一段 JSON 字符串，你要把它变成 Python 字典才能处理
raw_json = '{"name": "report.txt", "tags": ["important", "draft"], "size": 1024}'
parsed = json.loads(raw_json)
print(parsed["name"])  # report.txt
print(parsed["tags"])  # ['important', 'draft']

从文件里读写 JSON

# json.dump（没有 s）= 直接把字典存成 JSON 文件
data = {"name": "report.txt", "size": 1024}
with open("config.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2, ensure_ascii=False)

# json.load（没有 s）= 从文件里直接读取成字典
with open("config.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded["name"])  # report.txt

记忆口诀：带 s 的是操作字符串（string），不带 s 的是操作文件（file）。

函数方向用途
json.dumps(data)dict → str转成字符串（发 API 时用）
json.loads(str)str → dict解析字符串（收 API 时用）
json.dump(data, f)dict → 文件存成 JSON 文件
json.load(f)文件 → dict读取 JSON 文件

Python 安装和依赖管理：Conda/Pip

安装 anaconda 命令行conda -V，出现版本号，命令行python —version，出现版本号。

依赖是什么

我们在运行一个 Python 程序的时候，你很有可能需要依赖于其他人写的代码，或者仓库，而这就是 Python 的依赖。 比如你在学习机器学习，你很有可能就要依赖于下面这些库来写代码：

  1. tensorflow
  2. pytorch
  3. sklearn
  4. numpy

pip

是 Python 的库管理工具。

  • pip 是最底层最原始的 Python 库管理工具，安装一个 Python 就自带一个 pip，每个版本的 Python 都有自己私有的 pip。你可以想象成 pip 是 Python 的跟班。
  • conda 是在 pip/python 之上，想要隔离 pip 和 Python 环境的组件，所以是用 conda 来管理不同的 python 版本的。 pip安装方法:
pip install numpy # 安装最新的 numpy 
pip install numpy matplotlib # 一次性安装多个依赖 
pip install numpy==1.19.4 # 强制安装特定版本的库

conda分项目管理

conda 比普通的 pip 要更进一步，它可以分项目来管理依赖和 Python 版本。比如我有很多项目，里面的 Python 版本和依赖都不相同，我更愿意用 conda 来为这些项目单独管理一个 Python 和隔离他们的依赖。 首先，你需要创建一个 conda 环境 env，定义这个环境的名字和 Python 版本。

conda create --name Curry python=3.8

然后手动切换到这个Curry环境中，不然会一直待在一个base基础环境中。

conda env list # 可以看到当前有哪些环境
conda activate Curry # 切换环境 

# 现在终端前面有 (Curry) 标志
(Curry) C:\你的项目文件夹>

pip install xxxx # 现在安装依赖就不是全局安装而是针对这个环境安装了

然后在你新建的环境中，直接用 pip 安装你想要安装的库吧，现在所有用 pip 安装的库，都会隔离开，单独存放在 Curry 这个独立环境中。和 base 或者其他环境都不影响。 Conda 环境默认不放在你的项目文件夹里，而是集中管理，可以在anaconda文件夹中找到：\anaconda3\envs\Curry\

迁移依赖

使用requirements.txt文件存放pip依赖的列表。 可以通过以下指令生成：

pip freeze > requirements.txt

他会显示这个 Python 版本 pip 中所有安装过的依赖。如果你是用 conda 分项目来建 Python 的依赖环境的话，那就是这个 conda env 中的所有 pip 依赖。 获得了别人给的requirements.txt，如何安装依赖？

pip install -r requirements.txt
